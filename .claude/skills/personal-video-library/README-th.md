# personal-video-library

*[English](README.md)*

ชั้นประสานงานบางๆ ที่ทำให้การเขียน prompt ยึดโยงกับคลังคลิปอ้างอิงส่วนตัวของผู้ใช้ที่
`video-library/` (root ของโปรเจกต์) ที่กำลังเติบโตเรื่อยๆ และทำหน้าที่ตัด default "ก็อปตรงๆ"
ออกไปอย่างจงใจ — พอส่งคลิปอ้างอิงมาแล้วขอ prompt แบบครีเอทีฟ พฤติกรรม default ที่ไม่ถูก
บังคับคือการก็อปมุมกล้อง/เอฟเฟกต์เดิมเป๊ะๆ แม้จะสั่งให้ creative แล้วก็ตาม skill นี้ทำให้ขั้นตอน
เพิ่มความครีเอทีฟเป็นส่วนบังคับของ workflow ไม่ใช่แค่ทางเลือก

## ใช้เมื่อไหร่

- ผู้ใช้ส่งคลิปอ้างอิงมา (หรือชี้ไปที่ entry ใน `video-library/<slug>/`) แล้วต้องการ prompt
  generate ใหม่ที่สร้างจากคลิปนั้น
- ผู้ใช้อยากเช็ค `video-library/` ก่อนเริ่มงานเขียน prompt ใหม่ ("มีคลิปแบบนี้เก็บไว้ไหม",
  "เคยเก็บ reference อะไรแบบนี้บ้าง")
- ผู้ใช้อยากเพิ่มคลิปใหม่เข้าคลัง

ไม่ใช้กับการค้นหาเทคนิคเฉยๆ ที่ไม่มีคลิปอ้างอิงเกี่ยวข้อง (ใช้ `melies-cinematic-library`
อย่างเดียวพอ) และไม่ใช้กับการ QA คลิปที่ generate แล้วเทียบกับ prompt ของมันเอง (ใช้
`reelbench-skills` Phase 3/4)

## Workflow (ดู `SKILL.md` สำหรับรายละเอียดเต็ม)

1. **เช็คคลัง** — อ่าน `video-library/INDEX.md` ว่ามีอะไรเกี่ยวข้องอยู่แล้วไหม
2. **วิเคราะห์คลิปใหม่** — ส่งให้ `reelbench-skills` Phase 1 วิเคราะห์แบบวัดจริง ไม่ใช่ดูด้วยตา
3. **บังคับเพิ่มความครีเอทีฟ** — ดึง 2-3 เทคนิคที่มีชื่อจริงจาก `melies-cinematic-library`
   ที่เข้ากับ mood และยืนยันแล้วว่า**ไม่มี**ในคลิปอ้างอิง นำเสนอให้ผู้ใช้เห็นชัดเจนก่อน
   แล้วค่อยส่งต่อไปเขียน prompt จริงพร้อม brief ที่วัดได้และเทคนิคที่เลือกเป็นคำสั่งชัดเจน
4. **บันทึก entry** — เขียน/อัปเดต `video-library/<slug>/notes.md` และแถวใน
   `video-library/INDEX.md` ไม่ว่าจะเก็บไฟล์คลิปจริงใน repo ได้หรือไม่ก็ตาม

## ความสัมพันธ์กับอีก 2 skill

| Skill | ตอบคำถามว่า |
|---|---|
| `reelbench-skills` | "ฟุตเทจอ้างอิงนี้มีไวยากรณ์ภาพแบบไหนจริงๆ วัดออกมาเป็นตัวเลข?" |
| `melies-cinematic-library` | "เทคนิคกล้อง/แสง/เอฟเฟกต์นี้มีชื่อเรียกที่ถูกต้องว่าอะไร?" |
| `personal-video-library` (ตัวนี้) | "ฉันเคยเก็บอะไรไว้บ้าง แล้วจะมั่นใจได้ยังไงว่า prompt ใหม่เพิ่มเติมจากคลิปอ้างอิง ไม่ใช่แค่ก็อปมัน?" |
